# ecomcn — working rules

The full rules are in CONTRIBUTING.md; these are the ones most easily missed.

- **Motion, with a morph, on every block.** Anything that changes shape — a
  dialog, a sheet, a panel opening, an image moving — animates with `motion`
  (`motion/react`) and morphs from where it came from: a dialog grows out of
  its trigger, a panel grows to its measured height. One curve everywhere,
  `{ duration: 0.45, ease: [0.2, 0, 0, 1] }`, no springs or bounce. Switch the
  primitive's CSS keyframes off and keep it open until the exit has played.
  Reduced motion means a plain fade. Hover and colour stay CSS transitions.
  Reference implementations: `product-quick-view` (shared `layoutId`),
  `size-guide-dialog` (container transform with `animate()`),
  `product-details-accordion` (height to `auto`).
- **Both shadcn bases.** A block must compile and run on Radix and Base UI:
  no `asChild`, no `render`, and no base-only prop on a primitive's root — it
  reaches the other base's DOM and breaks hydration. Check with a dev-mode
  render, not just a build.
- **Registry sources live in `src/registry/`.** `src/components/ecomcn/` is
  generated by `scripts/sync-registry.mjs`; never edit it by hand.
